# Beacon 0.1.0-beta.1

Beacon 0.1.0-beta.1 is a synthetic-evaluation source release for product
manufacturers assessing a self-hosted vulnerability-response workflow.

## Included

- Private anonymous or identified report intake with recovery-token access.
- Staff triage, assignment, internal/reporter-visible conversation separation
  and audit history.
- Encrypted evidence and case data, controlled export, backup/restore and
  forward-only migrations.
- TOTP/recovery controls, optional OIDC, encrypted SMTP outbox and English /
  French server-rendered pages.
- Generic production configuration, backup/restore and optional monitoring
  integration examples.

## Evaluation status

The public CI checks pass on the published source. Use synthetic information
only. This beta is not a supported production release, legal certification or
an assurance that a deployment meets a manufacturer's CRA obligations.

Before accepting confidential reports, each deployment still needs its own
HTTPS, identity/MFA, SMTP, secret storage, backup custody, recovery drill,
capacity limits, accessibility/browser review, human coverage and independent
security review. See [DEPLOYMENT.md](../../DEPLOYMENT.md),
[THREAT_MODEL.md](../../THREAT_MODEL.md) and the operator documentation.

## Known boundaries

- PostgreSQL evidence storage has not been qualified for the original 500 GB
  target or sustained production concurrency.
- The included monitor is an optional customer-managed integration example,
  not a Beacon-hosted alerting service.
- Beacon does not decide legal applicability or submit reports to ENISA.
- No default credentials are shipped; local evaluation credentials are created
  in the ignored `.env` file.

## Feedback

Please use public issues for reproducible, non-sensitive evaluation feedback
with synthetic or redacted data. Send unpublished vulnerabilities only through
the private channel described in [SECURITY.md](../../SECURITY.md).
